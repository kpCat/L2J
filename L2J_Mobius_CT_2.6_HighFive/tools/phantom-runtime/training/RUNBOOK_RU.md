Был STOP_UNCONFIRMED, строгий90min gate FAILED: списано консервативно96.720667min, включая задержку recovery; точный native exit неизвестен. Использованы10GS starts. Финально собственные процессы остановлены, порты свободны, config OFF, faults/GUI hold выключены; acceptedTEST2 и MAIN/PLAY сохранены. Реальные6GUI handlers,2окна/1Director и закрытие GUI проверены. Ночной режим не готов; в текущем исчерпанном acceptance profile новые запуски запрещены указанием владельца. Команды ниже описывают интерфейс для будущего отдельно согласованного пользовательского профиля. Подробности — RESULT/EVIDENCE009.

В сохранённом отдельном TEST-клоне дважды щёлкните `TRAIN_GUI.cmd` из этой папки. Нужны Windows PowerShell5.1, JDK25, Ant и существующая собственная установка TRAIN с сохранённой SQL/Geo. Интерфейс собирается штатным `Add-Type` в частный runtime.

1. Нажмите **«Учиться»**. Director проверит владельца, исходники, JAR, Geo203/protected207, порты, SQL и холодный model/Adam checkpoint. Второй START присоединяется к работающему Director.
2. GUI и Codex можно закрыть. Обучением владеет отдельный broker. Повторный запуск GUI получает статус через CLI с проверкой живого owned процесса.
3. **«Пауза»** завершает атомарную операцию, сохраняет границу и закрывает native workers/SQL. **«Продолжить»** восстанавливает ту же кампанию и terminal Adam в новом Director. Зарезервированные эпизоды заново не исполняются.
4. **«Стоп»** штатно закрывает свои GameServer/workers/SQL. Дождитесь подтверждённой остановки и свободных портов. На следующий день нажмите **«Продолжить»**.
5. **«Экспорт»** при активном Director ставит запрос в очередь до безопасной границы. При остановленном Director экспорт выполняет существующий trainer/store.

CLI остаётся доступным:

```powershell
.\Training.ps1 -Action Start -Autonomous
.\Training.ps1 -Action Status -Json
.\Training.ps1 -Action Pause
.\Training.ps1 -Action Resume -Autonomous
.\Training.ps1 -Action Stop
.\Training.ps1 -Action Export
```

Исходный `AutonomousTraining.ini` выключен. Рабочие настройки после первого запуска находятся в `.phantom-local/learning002/train/TRAIN_CONFIG.ini`; меняйте их после Stop. `classes=auto` использует весь PlayerClass; `levels=auto` — заданный диапазон. Skill ID перечислять не нужно. Нужен сохранённый законный acquired source: отсутствие персонажа или adapter остаётся диагностикой; навыки автоматически не выдаются.

Настройки сеанса: `autonomous009DurationMinutes`, `cpuCount`, `cpuBudgetPercent`, `maxHeapMb`, `autonomous009MemoryBudgetMb`, `minFreeDiskMb`, частота EVAL, action families, уровни и class weights. CPU budget — ограниченный JVM processor count и пауза между батчами; кратковременный пик возможен. Память и диск проверяются во время workers/native. Базовый acceptance ceiling6/90 был явно расширен владельцем до10/90 только для этого Goal; использованные счётчики не сбрасывались. Строгое соблюдение90мин не подтверждено и не объявляется PASS. Обычный ночной профиль отдельно от acceptance smoke; его готовность в009 не доказана. Windows sleep/power settings не меняются.

Данные009: `autonomous/v1/campaigns/<campaign>/` — фаза Director, immutable manifests, failed/timeout/reserved попытки, отдельные EVAL и checkpoints. Достаточный новый cohort обучает существующую V3 с сохранением terminal optimizer lineage. Три sufficient fit без улучшения TUNING дают PAUSED; повторный недостаток evidence ограничивает цикл. Улучшение MSE не означает улучшения боевого поведения. Автоматического продвижения в accepted TEST или MAIN/PLAY нет.

После sealed cohort изменение source/JAR даёт pin refusal. До первого sealed cohort допускается записанный pre-CUT source revision с сохранением cumulative бюджета. Не удаляйте журналы для обхода отказа при чужом PID, занятом порте или повреждённом checkpoint.

Фактические проверки и ограничения009 перечислены в task package `PHANTOM-LEARNING-009-UNIVERSAL-AUTONOMOUS-TRAINER`; финальный manual gate требуется отдельно. Далее сохранены исторические инструкции.

Рабочая папка команд: `L2J_Mobius_CT_2.6_HighFive/tools/phantom-runtime/training/`
в отдельном клоне ветки `wip/phantom-learning-002`.

| Команда | Действие |
|---|---|
| `TRAIN_START.cmd` | Проверить собственную установку и запустить независимого директора. Консоль после запуска можно закрыть. |
| `TRAIN_STATUS.cmd` | Показать текущую фазу, heartbeat, реальные эпизоды, события, модель и причину ожидания. |
| `TRAIN_PAUSE.cmd` | Закончить текущий эпизод и приостановить выдачу новых. Дождитесь состояния `PAUSED`. |

Первый START может занять несколько минут: директор сам собирает собственный код,
готовит отдельный GameServer, копирует проверенную GeoData, устанавливает полную SQL-схему
в отдельную MariaDB и создаёт обычных тестовых персонажей. Ручные SQL и копирование Geo
не нужны. Все пути определяются от местоположения скриптов; команда работает из любого cwd.

Данные находятся в `<clone>/.phantom-local/learning002/train`. Рабочая игра и историческая
тренировка001 не используются для записи. По умолчанию endpoints только loopback:
SQL33327, GameServer17971, Login19271. Одновременно материализовано не более 5 актёров;
JVM получает 4 CPU и до 4096 MiB heap. Ноутбук должен оставаться включённым.
Запускайте команды в обычном сеансе Windows: повышение прав не требуется.
Один GameServer обслуживает до 6 эпизодов за батч. Перед эпизодом разрешено до 420 секунд
обычного восстановления персонажей; если сцена не проходит правила, она получает
причину отказа, а директор выбирает следующую. Подготовка не выдаёт фиктивный урон.

Повторный START при работающем директоре показывает его статус. PAUSE и STOP не
обрывают разрешённый эффект посередине. После неожиданного завершения повторите
RESUME: директор проверит точную identity оставшихся собственных процессов,
сохранит неполный эпизод без учебного credit и продолжит с долговременной границы.
Чужой процесс или занятый порт дают отказ с причиной.

Параметры находятся в `TRAIN_CONFIG.ini` рядом с командами. Изменения seed, режимов,
лимитов и следующей сцены применяются на безопасной границе батча. `modes=SOLO,PARTY`
нужен для выборки по обоим PvE-направлениям. Каталог возможностей проверяется по
реальным данным игры: наличие класса в списке не добавляет ему отсутствующих навыков.
Смена endpoints у уже созданной установки требует отдельной установки.

В статусе `COLLECTING` ещё недостаточно независимых данных для обучения. `DRAFT`
означает сохранённого кандидата, который не прошёл проверку качества; прежняя принятая
модель остаётся доступной. `ACCEPTED` относится только к этой TEST-установке.
Экспорт не устанавливает модель в рабочую игру. При работающем GameServer EXPORT
сохраняет запрос в очередь и возвращает его идентификатор: это ещё не готовый ZIP.
Директор обрабатывает запрос после штатного завершения текущего батча. Результат
записывается в `export-result.json`: `COMPLETED` либо `FAILED` с причиной; ZIP — в `exports/`.
Если директор остановлен, EXPORT выполняется сразу. При отсутствии принятой модели
немедленный экспорт возвращает ненулевой код; запрос из очереди получает `FAILED`,
а тренировочная кампания продолжает работу.

Отчёт: `<installation>/report.md`; машиночитаемый статус: `status.json`;
результат оценки: `evaluation.json`; история запусков и исходные журналы:
`attempts/`, `workers/`, `logs/`. SQL-данные и веса сохраняются после STOP.
Не удаляйте папку установки для исправления ошибки: сначала прочитайте STATUS/REPORT.

Текущий обучаемый action space — подтверждённые атакующие навыки Solo/Party PvE.
Полный PvP/PK, Raid, Siege, TW, Olympiad, Summon, Heal, Control, Spoil/Sweep и Move
не реализованы как обучаемые направления002. Наблюдение штатного вспомогательного
лечения в Party не означает готовую обученную healer-policy.

сами по себе не доказывают, что уже проведены новые игровые эпизоды.
