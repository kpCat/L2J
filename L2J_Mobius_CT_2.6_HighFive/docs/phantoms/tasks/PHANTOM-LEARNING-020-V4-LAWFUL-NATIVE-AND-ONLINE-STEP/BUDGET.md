# Бюджет и ранний STOP

**Не дробить на микрозадачи.** Codex выполняет один цельный vertical slice. Техническая цель — не провести как можно больше тестов, а завершить настоящую V4 цепочку.

- Рекомендуемое мышление Codex **High**, отдельный новый диалог.
- **T+0–15мин:** fresh GitHub/owner/test safety и read-only evidence. За 15мин — конкретная оценка возможности использовать 016 lawful scene, анализ `V4_NO_LAWFUL_SOLO_OPENING`. Если 016 data доступны лишь в частной TEST среде, работать с ними только там, без copy to Git.
- **T+30–35мин:** должна быть работающая реализация single-scene entrypoint и пройден focused offline route. Если живой сценарий без новых систем/неразрешённых правок не получается — STOP и дай 1–2 конкретных альтернативы, не начинай долгую реализацию окружения.
- **T+55мин:** если нет native proof или допустимого new V4 sample — остановиться и сохранить диагностику, не наращивать scope.
- **Target wall ≤65мин**, hard cap **75мин** с публикацией. Это предел затрат, **не гарантия успеха**. Не начинать операцию, которую нельзя безопасно остановить до cap; cleanup/drain не прерывать небезопасно ради таймера.
- Не более **одного GS boot**, включая startup/drain total **≤8мин**; private SQL и owner process тоже bounded; **никакого второго native запуска после отказа**.
- Focused offline test **≤120сек за один**, суммарно **≤12мин** всех verification (включая native); без теста длительнее 15мин.
- Не более **2 причинных исправлений** после первого native обнаруженного blocker, каждое с RED→GREEN, но **без второго boot**. Третий независимый blocker или существенный architecture fork — STOP.
- User может остановить Codex; по STOP native-owned процессы штатно drain/cancel, записи не переписывать. Публикация отчёта допускается после STOP, но новых тестов нет.
- Не делать отдельную бессмысленную микрозадачу из каждого отказа — записать причины и предложить архитектурный выбор владельцу.
