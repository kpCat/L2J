# Compatibility, crash and commit windows

| Window | Required result |
|---|---|
|Old PNC1 completed with points1|Legacy roundtrip/eligibility/rewards remain compatible|
|Old PNC1 non1 or UNKNOWN|Readable, no manufactured V2 FARM permission|
|Old PNC1 PENDING plus owned receipt|Exact before/after restore as before; new decoder must not discard receipt|
|V2 capture before PREPARE commit|No partial policy publication|
|After native PREPARE, before canonical store|Existing resolver selects exact before snapshot+before policy|
|After native store, before FINALIZE|Existing resolver verifies after int vitality and policy binding, finalizes once|
|After FINALIZE|New native admission sees committed state and policy; no duplicate awards|
|Background transaction before commit|Rollback state/vitality/XP/items/catchup together|
|Background connection loses commit reply|Resolve exact idempotency key with committed state/policy; no blind replay|
|Background successful commit then process crash|Read coherent new state/context at restart|
|New native demand during offline model calculation|One writer only. Either txn commits before native read or conflict/retry; no concurrent divergence|
|Model/rate/generation change|Old policy blocks relevant FARM, safe store still possible; fresh attestation normal path|

Changing the parallel native context codec is allowed; changing the native owned receipt
format or b4 crash-consistency semantics is not. Version2 payload max1024; Version1 original
bounds/header/enum ordering preserved. Keep compatibility overloads explicit, no implicit
legacy conversion that marks dynamic/premium/party contexts supported.

Fractional policy note: native persistence already serializes integer vitality. Background
may retain its own float within V2 between batches, but native admission/capture resets that
fraction by the documented native integer projection. This is tested provenance, not a
hidden resource restoration. No reward is generated by capture/rebind/schema migration.

Final actual crash evidence must name final SHA because transaction/context code changes.
At most two own crash lanes per TASK. Deterministic fault tests cover remaining windows.
Never claim old027 actual crash is a final029 actual crash.
