# Реализация протокола012 V2

Additive TEST-only протокол включается явным `evaluationOutcomeVersion=2` при frozen EVAL-only, exploration=false и лимитах не более2GS/35мин. Без opt-in остаётся прежний V1 путь. Production learning/reward/Combat/Party/Player/Spawn и SQL schema не меняются.

`EVAL_ARM_V2` — отдельный bounded binary codec; `EVAL_PAIR_V2` и `EVAL_PAIRS_V2` — отдельные JSON artifacts. Native reservation, CUT, settlement, actor/NPC incarnations, native event keys и exact source receipt hashes сохраняются. Settlement hash проверяется по canonical typed episode. Старые `completed`/V1 файлы сохраняют прежнее значение legacy both-goal-success.

Comparable terminal требует равных подтверждённых physical facts, source/build/config/frozen model authority, seed/context/stratum; противоположных сторон и позиций; достоверного admission/CUT/terminal/settled/deadline; свежих actors/targets/events внутри пары и всей кампании. Смерть не требует наличия paid effects. Goal success определяется linked target kill отдельно от observed death lower bound и terminal dead snapshot. Настоящая смерть, включая recorded death при последующем живом snapshot, учитывается в losses.

Timeout comparable только при exact native deadline и settlement, отсутствии kill/death и cancellation. Это censored within-window outcome; будущая победа UNKNOWN. Stop/cancel/stale/missing/unsupported/corrupt evidence не превращается в поражение. Reserved arm читается повторно только из immutable evidence; native dispatch для него не повторяется. Malformed arm получает typed incomparable и конкретный refusal. Partial snapshots имеют content-addressed имена; окончательный immutable aggregate публикуется после полного набора.

Новый `terminal-boundary-v2.json` связывает CUT/terminal/settled/deadline, ownerNonce, admission и settlement hash независимо от paid events. Для каждого paid effect `native-authority-v2.json` сохраняет настоящий typed callback owner, decision/actor identity и raw native record hash. Reader проверяет offered legal mask, decision generation, actor/target/profile, owner witness, model version, observed HP/MP delta и native timing. Supplemental legacy `native-admission.json` содержит Java Map text в sessions и не объявляется valid JSON. Initial Party session generation может отличаться от последующего настоящего cast owner.

Legacy011 replay работает только после совпадения всех230 original raw-file hashes с опубликованным011 inventory и exact archived active config. Отсутствующий новый V2 owner witness не выдумывается задним числом: происхождение старого record подтверждается immutable inventory и canonical source callback contract. Новые V2 arms требуют свой witness. При отсутствии private evidence authentic replay запрещён.

Curriculum использует только до-CUT факты: canonical NPC level/HP/defense/attack, реальные исходные HP/MP состава, target-bound acquired alternatives/MP costs, source/equipment/inventory fingerprints. Native eligibility/Geo/LOS/faction/reward/owner gates011 сохраняются. Сначала строится bounded lawful список до12кандидатов, затем deterministic seed183 выбирает LOWER и HIGHER relative burden по направлению; ties не создают искусственных категорий. Labels относительны к конкретному roster/catalog. Дополнительный pre-GS gate требует фактически разных selected burden vectors Solo и Party. Candidate facts, выбранная категория, source/config/seed и порядок A/B запечатаны до боя; исходы, neural scores и вероятность победы не используются. DPS/mortality/win probability UNKNOWN.

Отдельно Solo/Party считаются terminalComparable, bothGoalSucceeded, withDeath, timeout, incomparable, learned-only/stock-only/both/neither wins. Kill time delta существует только при двух kills; terminal duration не называется временем победы. Неизвестные whole-party/economy/complete-death metrics остаются null. Paid legal divergences не равны ranking changes. Wilson95 описывает per-side success при конкретном n пар; exact two-sided sign test использует только discordant pairs. Четыре пары не дают утверждения о превосходстве: verdict INCONCLUSIVE.

Техническое FULL012 требует G0–G8. Manual acceptance владельца всегда REQUIRED. №6/13; осталось7; следующий Goal автоматически не начинается.
