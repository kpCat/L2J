# EPIC_STOCK070 — new persistent shop, not static infinite multisell

**User behavior**: Alt+B -> Epic Jewelry, show each verified unique epic item by actual name, icon, requirements, current global stock (0/1), native currency/price (may be >2.1b nominal), and **next replenishment UTC**. Sold-out visible but disabled with clear reason. No fake sold-out based on per-player cache; stock shared for every normal real account. This is a normal `HomeBoard`/server-side HTML dynamic render, with safe client-native bypass and no client files. Classic NPC boss drops unaffected.

**Whitelist** 12 source IDs from `PhantomEpicItemPolicy`: 6656,6657,6658,6659,6660,6661,6662,8191,10314,16025,16026,21712, subject to real item templates and boss source/safe trade. Each SKU has global maxStock1. New own070 DB initialization can create initialStock1 ONCE per SKU after exact schema ownership check; per tier 14/30/60-day replenishment defaults in PRODUCT_DECISIONS.md, configurable without source recompile. Reference UTC instant persisted, monotonic rate, restart and daylight shifts do not create new items. If when elapsed since last sale multiple cooldowns pass, **do not accumulate infinite stock**: max1 remains. No more than one unit per account per SKU per replenishment epoch (persisted ledger) to avoid same-account rapid refresh.

**Durable DB design** (use actual migration naming project style and idempotent own070 setup): `epic_shop_stock(sku PRIMARY KEY, currentStock, maxStock, nextRestockUtc, restockPolicy, version, sourcePriceRevision)` + purchase/order receipts with immutable unique request IDs, account/char identity, cost+currency+SKU and status. All state changes use SQL transaction/lock or optimistic CAS on version, uniqueness, monotonic `nextRestockUtc`, and native item ownership checks. Buy and delivery cannot double-issue after restart / simultaneous requests / process crash. **Do not claim DB transaction automatically includes Player.exchangeItemsById memory writes**: if two separate writers, use durable payment/delivery journal, reconcile single recorded transition and fail-closed pending before further buys; prove exactly-once. Use DB native mysql/MariaDB transaction primitives, bound connection handling, not a process-global lock alone.

**Prices > MAX_ADENA**: we cannot just set XML ingredient count to 24b (native player may hold <=2,147,483,647 Adena). Provide a named, account-bound `Epic Savings` ledger in BIGINT backed **1:1 by real deposited Adena** from ordinary inventory with idempotent deposit/withdraw/cancel and durable exact receipts, amount limits, account access0, no phantom/headless fake privilege, no cross-account gifts, no tradeable temporary item/client patch. Deposit can be repeated in amounts within native per-operation/account cap; wallet may exceed ordinary carried Adena cap, and purchases debit wallet precisely once. Withdraw only up to character's remaining Adena room; a full inventory cannot destroy money. If engine's stock inventory transaction cannot atomically coordinate with ledger, implement journal/replay safety with automated reconciliation; if a pending state remains ambiguous, BLOCKED_LEDGER_SKU; do not credit items or destroy currency speculatively. Never create currency from a refund loop; controls include failed deposit, concurrent deposit/buy, crash recovery, restart, offline character, cancelled order, stale quote. Do not deposit phantom startup seed/negative price.

**Race tests**: two ordinary test actors across two DB connections try to buy last stock1; exactly one debit + one issued real item, other unchanged. SameDB restart repeat same request; 0 new stock, no duplicate item, no issued credit. Advance a test-only injectable clock for replenishment without changing OS time, show stock1 after due and 0 otherwise, persist next restock; test same account limit, quote race, price plan change during open HTML. When stock0 do not execute native item writer. Testing must not mutate REAL epics in protected DB.

**Policy**: rare drop boosted by premium still remains legitimately earned; epic shop is a SECOND, more expensive and scarce path. Never auto-reseed epic stock on task/release boot. No API to grant epic items without paying except owner-controlled DB test bootstrap / verified quest rewards. No item sale when boss source canonical unknown; this is a visible reason, not silent infinite fallback.
