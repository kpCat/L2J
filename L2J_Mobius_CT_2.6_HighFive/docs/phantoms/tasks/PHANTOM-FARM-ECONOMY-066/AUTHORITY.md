# AUTHORITY066 — разрешения владельца и бюджет

Это прямое заранее выданное разрешение реализовать TASK.md целиком в указанном scope. Не останавливаться после read-first/плана/RED/GREEN, не спрашивать разрешение на связанные файлы, тесты, commit/push или продолжение. Отсутствие владельца ожидаемо; USER_ABSENT не blocker.
Системные разрешения платформы, безопасность и реальные права доступа не обходить. При таком запрете зафиксировать BLOCKED_PLATFORM и продолжить независимую работу, а не просить владельца логиниться в игру.

## 1. Разрешено
- Править связанные Java/config/XML/test/Ant/PowerShell и документацию High Five. Разрешено больше10 файлов по общей причинной цепочке; точный allowlist вести в CHANGED_FILES066.txt.
- Исправлять общие причины в исходных owners, включая малый shared seam для stock хозяйственных действий. Перенос core logic из packet handler допустим только без регрессии обычных игроков и без второго implementation.
- Самостоятельно выбрать ближайший существующий аналог/имя нового компонента, выполнить RED→GREEN, устранить непосредственные blockers на этой цепочке. Не превращать каждый blocker в новый чат/suffix.
- Читать необходимые private local configs для подключения к своей среде, не раскрывая секреты. Создать/инициализировать только новые066 схемы и изолированный candidate по RUNTIME_INPUTS.md.
- Собрать JAR, запускать и штатно останавливать собственные Main/native fixtures, читать логи и свои DB rows, использовать private observer и точечную диагностику своего процесса.
- Thread dump/JFR/jcmd или отладка только точного своего PID/incarnation. Не добавлять сетевой debug listener по умолчанию; при необходимости только loopback своей диагностической JVM, не финального candidate.
- Подготовить до measurement именованные TEST fixtures с честно отмеченными предметами/навыками/позицией; использовать реальные шаблоны и known skills. Это не свидетельство игрового происхождения fixture вещей.
- Создать локальные commits и обычный push в feature/phantom-world, включая безопасный частичный результат с честными статусами. Дополнительного подтверждения не требуется.
- Точечно обновить CURRENT_STATUS/revised roadmap новым фактом; не удалять исторический roadmap и не редактировать старые отчёты ради нового PASS.

## 2. Безопасные границы
Защищены release057–065 и их БД/TEST, MAIN/PLAY, клиент, Studio, Account_Manager, чужие worktrees, legacy C:. Чтение проверенных runtime ресурсов допускается, запись/запуск этих сред — нет.
Запрещены force push, reset --hard, clean, stash, force checkout, add . / Stage All, удаление worktrees, rebase/cherry-pick/merge-commit и изменение master/origin/master/upstream/master/default branch.
Не изменять MariaDB service/datadir/users/grants, firewall, сетевые настройки ОС; не устанавливать/обновлять JDK/Ant/.NET/зависимости. Наличие старых credentials в документах не является разрешением использовать их вслепую.
Не управлять реальным персонажем владельца, не создавать ему новую сессию и не выдавать GM. Не обходить LocalPlay consent/ACL/JAR/instance/identity guards.
Не выполнять crash72/73, Stop-Process -Force/taskkill, массовую остановку Java. Зависшая своя JVM → штатный stop + диагностика + честный blocker, без насильственного освобождения чужих портов.
Не менять HP/damage/rates/drop/spoil chances/таймеры посреди проверяемой сцены; не пополнять Adena/MP/предметы и не телепортировать фантома для PASS.

## 3. Git-процесс без потери пользовательских изменений
Разрешены bounded status/rev-parse/symbolic-ref/worktree list/for-each-ref/ls-tree/merge-base/diff/log/show/ls-remote, exact fetch только feature/phantom-world, fast-forward-only при отсутствии конфликтующих изменений, archive, add -- <exact allowlist>, commit, push.
Перед работой: сравнить local HEAD с live `refs/heads/feature/phantom-world`. Новые совместимые descendants учитываются как новый baseline; записать SHA и узкий diff, не перечитывать всё.
Пакет066 — ожидаемые owner input files. Чужой dirt сохранить. При конфликтующих исходниках/неизвестной истории не reset/stash и не угадывать; отметить блокировку затронутого участка, сохранить независимые результаты.
Публикация: `git push origin HEAD:refs/heads/feature/phantom-world`. При non-fast-forward не force/rebase; сохранить local commit и отметить BLOCKED_REMOTE_ADVANCED. Успех push подтверждать live remote SHA, а не только exit0.
Передача готового JAR связывается с code commit/source archive. Последующие report-only commits могут иметь другой final HEAD; указать обе привязки, не выдавать старую сборку за новую.

## 4. Бюджет кампании — потолок, не обязанность жечь время
Общий ориентир владельца — до12 часов активной кампании. Закончено раньше → собрать и закончить раньше. Не заполнять остаток времени soak, новыми желаниями или повторными ревью.
Рабочие ориентиры верхнего распределения: read-first/environment до45мин; A+B до3.5ч; C до1.5ч; D до3ч; связанная проверка/финал — оставшийся бюджет. Это план ограничения расходов, не гарантия сроков реализации.
К отметке10.5ч новые функции не начинать: оставить время на завершение безопасных изменений, сборку, stop, отчёт и публикацию. Нестабильный свой кусок снять адресно, не трогая чужие правки; оставшееся обозначить PARTIAL.
Native ordinary наблюдения суммарно ориентир45–60мин, верхний предел90мин; автоматические тесты в целом не превращать в основную работу. При успехе критерия сцену сразу завершать.
Один и тот же native сценарий не запускать многократно без нового диагноза/изменения. Две неудачи → точечный trace + общий RED, не третий одинаковый забег с другим seed/названием.
Если45мин уходят в одну причину без проверяемого продвижения — пересмотреть архитектурный путь/минимальный seam; до20мин на исправление сугубо fixture plumbing. Не обходить продуктовый дефект ослаблением проверки.
В одной основной сессии без автоматического разветвления на множество исполнителей/ревьюеров. Финальный самостоятельный review focused diff обязателен, но не называть его независимым ревью.

## 5. Как экономить без потери качества
Первое чтение — закрытый набор; дальше точные symbols по этапам. Не перечитывать сотни отчётов после compaction: HANDOFF066.md хранит baseline, решения, текущий blocker, следующий шаг, выполненные gates и живые собственные PID.
Вместо race×spot×level brute force: полная проверка данных и несколько классов поведения/геометрии. Каждый патч должен объяснять общий нарушенный инвариант и проверяться хотя бы на втором представителе.
Запрещены исключения «только для этого Gremlin/Keltir/расы/координаты» без доказанной ошибки stock данных. SEARCH_LIMIT — исчерпание бюджета поиска, не доказательство отсутствия пути.
Сборки Ant последовательно. Во время работы только compile/affected tests. Общий `ant verify` НЕ разрешён этим пакетом: он содержит сторонние DB-targets; финал — явный impacted набор, чистый JAR и native evidence.
Не запускать проверки сохранности всех122 исторических схем каждый цикл. Достаточны строгие destination guards/own writer set и исходные/финальные hashes реально используемых read-only ресурсов; область проверки честно указать.
Фактические время/количество запусков/модельные расходы сообщить только когда доступны. Не угадывать токены, проценты лимита или цену. Логи сохранять локально, в контекст — summary и причинный фрагмент.
