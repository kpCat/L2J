## Факты и границы измерения
- Sample predicate060: берёт первые1024 World players, затем isSpawned/isOnline/exact World identity/OwnerKind.PHANTOM и до16 результатов. В нём нет фильтра расстояния; он не полный census. Именно поэтому0 не доказывает ни «они далеко», ни отсутствие любых Player. Указать охват/фильтры/времена при выводе.
- Данные ordinary должны быть привязаны к source/JAR/runtime/PID incarnation и времени. `mode=AUTONOMOUS` с fresh snapshot допустим; `actualNetworkSession=false` не становится REAL. Реальный пользователь не обязан логиниться для этих серверных фактов.
- Before episode: actors/classes/quest state/resources/loaded routes/goal source/deadline/ожидаемая плата объявлены. Подготовленные уровни/расписание — fixture input, не natural career. Ограниченная новая preview cohort не доказывает починку старой history.
- Во время W1 и положительного C20 test code не задаёт следующий goal/target/XYZ, не вызывает quest reward/onKill и не дополняет HP/MP/SP/items. Разрешены только обычные продуктовые решения и штатные действия, включая законные GK/recall/items.
- Уход/возврат и class change подтверждаются по фактическому Player и операциям, не словам «READY/ISSUED». CAST отдельно не равно effect; completion квеста отдельно не равно перевод класса.
- Гибель в законном бою может быть частью recover→continue. Нужно сохранить состояние и показать правильное продолжение либо конкретный непройденный исход; не менять старый input задним числом.
- Состав/место независимого нового эпизода менять можно до enrolment с причиной; завершившаяся отрицательная сцена остаётся в истории. Не требуется бесконечное испытание одного спота.
- Незатронутые прежние длительные сцены можно reuse с объяснением совместимости owner/code/data; два основных результата061 обязаны иметь реальные current end-to-end факты. Ещё одна одинаковая полная проверка без нового риска не обязательна.

## Неизменяемые negative boundaries
**World:** wrong owner, stale incarnation, no locality/legitimate sleep/initial-not-ready, exhausted capacity, false-positive sampling, отсутствующая геодата; диагностический code не меняет Player.
**Career:** wrong class/race/index, missing quest conditions/item/level, неверный script/hash, duplicate transfer/callback, сменившийся root, busy native cast, party/HOLD, повтор после рестарта. Специальное квестовое оружие реально используется там, где этого требует script.
**Conservation:** SP/items/marks/Adena и class skills после save/restart соответствуют только committed native операциям. Неизвестный SP conflict не превращать в кредит. Старые skills не стирать ради cache refresh.
