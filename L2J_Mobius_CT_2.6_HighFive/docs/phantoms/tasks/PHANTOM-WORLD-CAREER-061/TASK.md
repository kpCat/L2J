Preview/input подготовка явно отделяется от продукта. Детали решения после причинного read-first разрешены без нового согласования.

Своевременное появление не достигается hardcoded profile IDs, forced ACTIVE или живой перезаписью cursors. Старые release config не менять.
## 11. Производительность
Общий scheduler, bounded batches, диагностика через существующий observer/status. Никакой SQL-loop/таймер на каждого бота, global dump каждую секунду или миллионов файлов. Legacy sample limit1024/16 и30-секундный population snapshot не путать с полным census; при необходимости добавить факт охвата, не безлимитный scan.

После class change вернуть корректный continuation нового класса, не старое недействительное намерение. Stop не повторяет квест/плату/награду.
