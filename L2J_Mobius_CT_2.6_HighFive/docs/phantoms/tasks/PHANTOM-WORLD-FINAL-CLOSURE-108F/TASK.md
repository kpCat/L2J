## 1. Два открытых причинных пути

**World/observers.** Подтверждённый harness defect в `PhantomPopulation102Native.addObservers`: `regions.add(homeRegion)` выполняется **перед** `operatorLocalityTarget`, поэтому при пустом topology lookup регион расходуется и соседние кандидаты не пробуются. Исправить порядок reservation только после **успешного** target и фактической легальной регистрации observer; добавить bounded per-candidate lookup/admission outcomes и требование **ровно двух** настоящих test-human observers до World-gate для обеих кампаний. Не `spawn`/teleport фантомов за счёт теста; не синтезировать eligibility; не делать бесконечный перебор 5000 строк. Использовать уже существующие `operatorLocalityTarget`, `operatorSetupLocalityTarget`, `operatorAdmissionProfile`, `operatorStatus`, `operatorReadinessProgress`, `PhantomHumanLocalityControl.physicalSnapshot`. Если topology ещё не готова — **обоснованное ограниченное ожидание/повтор observer lookup** до запуска World-окна; логировать результаты, не увеличивать таймаут без необходимости. При невозможности иметь двух observers — доказательный STOP, а не запуск невалидного B.

**SP/skill.** Dwarven Fighter `classId=53`, skill `141:1 Weapon Mastery` в `DwarvenFighter.xml` стоит `levelUpSp=310`. Поэтому −310 **совместимо** с покупкой, но R3D не сохранила paired `character_skills` и статус SUCCESS конкретной транзакции. Не отключать/ослаблять `negativeRows`; не считать любое −310 допустимым. Добавить **отдельный** детерминированный bounded SELECT-only skills sidecar к pre/post native snapshots для подтверждённых владельцев `charId/class_index/skill_id/skill_level` (не переписывать формат/историю `Task105Census` и старые slices). Для каждого отрицательного SP: парная class identity + skill transition, canonical price из текущего skill tree, единственный конкретный native SUCCESS/commit (или явное UNKNOWN), отсутствие двойного применения и баланс `SP_after = SP_before + proven credits − proven paid costs`. Если нет доказательства единственного debit — BLOCKED. Не требовать искусственно совершить покупку в тесте; без отрицательных строк отклонять дубликаты/посторонние изменения, сохранять исходный отрицательный regression case.
