## Обязательные функции (всё — один законченный Goal)

1. **G0 / контекст.** Выполнить `CONTEXT.md` и `SAFETY.md`, проверить approved source SQL/Geo203/native 021, изоляцию, parent188 и два независимых read-only cold/replay checks. При несовпадении не запускать GS и не подменять parent моделью179.
2. **Единый V4 TEST controller.** Использовать существующие `Training.ps1`, `TrainingOwner.ps1`, broker/owned-process guards и V4 Decision→Intent→Effect→Feedback. Допустить узкий V4-adapter/controller, но НЕ второй боевой AI, не клон V3 campaign, не Java production scheduler. Отдельный явный CLI-профиль `ActionValue022`: `Start`, `Status`, `Pause`, `Resume`, `Stop`, `Report` (см. `RUNBOOK_RU.md`). Production OFF; старые команды 020/021 не меняют смысл.
3. **Автономная последовательность.** Не hardcode 179/`train021-c1`/старые порты как очередной шаг. На каждой границе берётся последний *подтверждённый* candidate, создаётся новый versioned attempt/episode, frozen pre-CUT policy и доказанный native owner. Использовать существующие `AutonomousTrainingV1` source/curriculum/shortlist, фактически изученные навыки и lawful admission; контролируемо менять legal кандидатные тактики, а не гонять одинаковый заготовленный CAST. Не выдумывать другие классы/споты, если private source не даёт lawful access. Предпочесть несколько эпизодов в **одном** owned GS с корректным state rearm вместо boot на каждый sample.
4. **Полный paid loop.** До исполнения фиксировать Plan/Decision/Intent (021 contract), после settle/drain связывать исходные native raw, row, Effect, epoch/owner/target/skill/eventKey/split/source SHA. Только authenticated TRAIN → `ActionFeedbackV4` и `ActionLearningV4.fit` с batch≤256; no receipt/unknown/heldout = no credit. Не менять HP/MP/skills/исходы, `label()` или 5ms native budget.
5. **Durable продолжение.** Сегментированный append-only ledger и create-only models; `reservation → native complete → verified batch → fit/cold → atomic committed HEAD`; crash/STOP/RESUME с exactly-once во всех сегментах, включая event keys 188. Реализовать доказуемый rollover **без потери истории** до лимита 4096 (архитектура в `ARCHITECTURE.md`), либо честный BLOCKED, а не ночной READY. Не очищать keys и не переобучать старые receipts.
6. **Пользовательский 8h сеанс.** Duration 480 минут задаётся конфигом/командой, автоматический STOP по сохранённому deadline, собственные pause/resume/stop, checkpoint/status/report, пороги CPU/памяти/диска/времени, no-data/stagnation и ограничение boot. `Status` не запускает сервер; закрытие GUI/диалога Codex не завершает owned controller. Ни одного обязательного 8h прогона на acceptance.
7. **Оценка качества.** В отчёте реальные раздельные HP damage, MP cost, elapsed, kills/deaths, mode, skill, per-action contribution, отказ/UNKNOWN, n/variance/coverage, lineage, разница stock/model/experiment и исторический baseline. TUNING/AUDIT — предзаданные независимые splits, без gradient и exploration; на малой выборке `SUPERIORITY=NOT_EVALUATED`. Не выдавать улучшение MSE или +updates за доказательство побед.
8. **Готовый пользовательский выход.** CLI-команды, human-readable report и machine-readable `status022.json`/`report022.json` в private TEST root, контроль endpoint/own-process, автоматическая остановка без Codex. Исторические V3/020/021, MAIN/PLAY, Semantic Studio, Geo, snapshots byte-identical.
