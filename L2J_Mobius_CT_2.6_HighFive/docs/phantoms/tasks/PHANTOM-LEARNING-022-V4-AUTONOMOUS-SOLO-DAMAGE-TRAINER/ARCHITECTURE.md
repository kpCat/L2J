# Архитектура Goal022: TEST campaign без второго боевого AI

## 1. Integration seams

- **Control:** в существующем `Training.ps1` отдельная явная action `ActionValue022` с `-ActionValue022Command Start|Status|Pause|Resume|Stop|Report` и `-ActionValue022Minutes` (1…480, default 480); новый узкий driver допускается отдельным `TrainingV4*.ps1`, вызываемым из router. Использовать `TrainingOwner`/`TrainingBroker` process identity, locks, shutdown, failure handling; не смешивать с `-Autonomous` V3 и GUI009. OFF by default, каждый Start — явное разрешение владельца на TEST.
- **Data:** private `train022/` рядом с существующим owned TEST `train`, не внутри MAIN/PLAY. Никогда не использовать `train021` или `train021-c1` как mutable target; parent188 и source cohort только read-only. Не коммитить private roots, SQL, реальные model bins и сырые receipts.
- **Decision:** те же `ActionExplorationV4.Plan/Decision`, `ActionExperimentReceiptV4.Intent/Effect` и `ActionFeedbackV4`; единственный owner. MODEL/BASELINE/COVERAGE/EPSILON различаются. Existing stock/legal native executor остаётся единственным источником выполнения; TEST-only V4 slot без второго перехватчика или hot-path disk I/O.
- **Native:** generalize лишь необходимый test-only runner 020/021: параметры candidate model SHA, root/ports/episode ID, sealed source image, dynamic TEST scene. Refuse stale/illegal/source mismatch. По возможности один запущенный owned GS обслуживает несколько последовательно подготовленных эпизодов; строго complete→cleanup/rearm→next, без переиспользования Player/owner lease/old SQL snapshot без доказательства. Отдельный native boot — не способ обойти отказ.

## 2. Состояния и сохранность

- Durable campaign identity = campaignId + schema + config SHA + immutable parent188 SHA + source catalog SHA + TEST environment pin; все attempts имеют независимые immutable `episodeId`, nonce, split, policy, modelSha, input files SHA и counter/seed, записанные **до** CUT.
- Директория каждого раунда: `reservation.json` (create-only) → `native.complete.json` (только после exact original receipt/drain) → `fit.complete.json` / create-only `candidate-<sha>.bin` → `cold.complete.json` (отдельная JVM) → `commit.json` → atomic durable `HEAD` на следующий step. Промежуточные файлы не перезаписывать; recovery валидирует SHA, owner, split, period и checkpoint lineage, затем коммитит уже доказанный шаг ровно один раз или блокирует; новая native попытка не восстанавливает данные предыдущей.
- Один writer с проверяемым lifetime process identity и durable lock; multiple START idempotent (status, не второй Director). STOP/Pause на безопасной границе; `STOP_REQUESTED` не выдавать за `STOPPED` до process absent, FREE ports и сейф-отчёта. При краше внутри native **UNKNOWN/ABORTED_NO_CREDIT** до доказанного complete; при краше после native complete — offline verified finalization без нового GS. Чужие процессы никогда не kill.
- Финальная durable status machine: `NOT_STARTED`, `RUNNING`, `PAUSE_REQUESTED`, `PAUSED`, `STOP_REQUESTED`, `STOPPED`, `AUTO_STOPPED`, `RECOVERY_REQUIRED`, `BLOCKED`. Status/Report — read-only без Java/SQL/GS.

## 3. Global anti-replay ledger и rollover

- До первого шага запечатать импорт exact internal eventKeys/fingerprints/episode split **из physical checkpoint188** во внешний append-only global ledger, включая 021. Связать в seal предыдущие accepted parent SHA и model bytes, все резервации и каждый committed segment. Reject конфликтующий eventKey даже после rollover; same event/same fingerprint = replay0, different fingerprint = tamper BLOCKED. TUNING/AUDIT никогда не получают SGD credit.
- Batch ≤256, `ActionValueV4.MAX_EVENTS=4096` **не изменять**. Перед FIT проверять batch capacity и границу segment. Parent model checkpoint и все seals immutable; new checkpoint publish before atomic HEAD. Atomic HEAD содержит compare-and-swap expected parent/segment/ledger SHA; crash между checkpoint и HEAD переиспользует доказанный результат без second FIT.
- **Важная техническая ловушка:** `ActionValueV4` V4/1 проверяет `updates<=events.size()`. Не пытаться просто очистить events, продолжить `updates>0` и назвать это rollover. Рекомендованный versioned `V4_SEGMENT_CONTINUATION_V1`: на rollover создать *новый segment* из **точных 128 weights предыдущего cold-verified checkpoint**, с local updates=0, пустым *segment-local* event/episode map и `parent=<previous checkpoint SHA>`; внешняя immutable global ledger хранит все старые keys/splits и общее `globalUpdates`, которое не сбрасывается. Helper в том же `phantoms.learning` package вправе использовать существующий package-private V4 ctor, не меняя исторический codec; seal связывает old/new weights, segment indices и global totals. Если эта схема не даёт доказуемой crash-atomicity/anti-replay — STOP `BLOCKED_ROLLOVER`, не подменять её silent truncation.
- При старте/RESUME сверять весь sealed ledger lineage и физический latest candidate. Любой недоказанный writer/lock, повреждённый seal или конфликт TEST source = fail closed. Near-cap/over-cap simulated fault tests не создают фиктивных native TRAIN credits.

## 4. Curriculum, метрики и критерий остановки

- `AutonomousTrainingV1.nextCandidate`/shortlist используют доступные acquired `DAMAGE` навыки с legality/MP/LOS/Geo/level/owner; выбор сцен с детерминированной ротацией source/class/target/skill из **реально доступных** исходников. Не заявлять diversity=multiple classes, если допустим только class94; фиксировать eligible/refused reasons, attempts, coverage и альтернативы. No safe candidate / 3 no-data итерации → `PAUSED_NO_DATA`/`AUTO_STOPPED`, а не endless GS restarts.
- Frozen pre-CUT `TRAIN/TUNING/AUDIT` для каждого episode, отдельно stock/control/model/explore; в TEST TRAIN ограниченное безопасное exploration из 021 policy. Не переименовывать COVERAGE(p=1) в randomized EPSILON; rejected decision не становится paid effect. Run-scoped seed не подбирать после outcome.
- Сравнения: measurable damage, MP, elapsed, полезная HP fraction, death/kill (только episode), per-skill/mode counts, mean/variance и неизвестные эффекты; pinned stock/previous/current по сопоставимым lawful contexts, independent TUNING/AUDIT не получают credit. Causal advantage из n=1/2 UNKNOWN; REPORT не пишет «модель лучше» по обновлению весов. Если нет достаточного A/B, `SUPERIORITY=NOT_EVALUATED`.
- Сохранённый абсолютный UTC deadline (duration≤480min) не сбрасывается Resume/перезапуском. Auto STOP при deadline (без нового эпизода за границей), disk free<8GiB, CPU/memory limits, noData, stagnation, capacity failure, invalid proof, safety breach. Manual Pause/Stop после drain и atomic boundary. Не изменять Windows sleep. Импульсы времени и возможный clock skew тестировать offline.

## 5. Разрешённый TEST-only запуск и документация

- Smoke: ≥2 distinct native episode IDs (не два разных имени одного event), ≥2 последовательных cold-confirmed checkpoints с глобальным updates ростом, ≥1 genuine alternative + baseline control в выбранной разрешённой TRAIN-сцене, и реальные read-only reports. Если за ≤2 GS нельзя получить эти факты законно, FULL невозможен.
- Высокий ROI: scene/admission dry-run, deterministic offline/fault tests, затем по возможности **2 эпизода в одном GS** (≤2 boots абсолютно). Не запускать 480мин до owner approval. После smoke клиентский `Start -ActionValue022Minutes 480` доступен, но acceptance report явно отмечает **8h NOT_RUN**.
