# IDLE_ROOT_CAUSE

В 16:47:05Z Pilot увидел естественно materialized и client-visible profile 123 рядом с REAL_LOGIN TestAdmin. `SELECT_VISIBLE_PHANTOM_TRACE` выбрал именно этот профиль; два снимка в 16:47:26Z и 16:47:58Z совпали: `goalType=farm.background`, `goalStatus=FAILED`, `runtimeState=TERMINAL`, `decisionSequence=2`, `candidateKey=null`, `lastResult=null`, `recorded=0`. Вокруг TestAdmin были три обычных monster objectId, но terminal Goal не допускал нового Goal→candidate→handler решения. `reasonKey=activity.generation_changed` показывает последнюю отмену плана, а не исходную причину записи `FAILED`.

Существующий `PhantomBackgroundService.recover()` возвращал `FAIL_GOAL` после успешного `death.recovered_at_town`; `PhantomBackgroundDecision.execute()` переводил его в `PhantomStepResult.FAIL_GOAL`, а `PhantomDecisionEngine` сохранял `farm.background` как terminal `FAILED`. Это единственный найденный production `FAIL_GOAL` путь для данного goal type. Трасса доказывает terminal состояние и отсутствие дальнейшей работы; связь конкретной прежней recovery операции profile 123 с этим статусом подтверждена кодовым путём, но сам прежний recovery event не сохранён в выбранной истории (`recorded=0`). Источник нельзя приписывать одному только `activity.generation_changed`.

Дополнительный независимый gap: живой WARM/ACTIVE материализованный `farm.background` в `PhantomBackgroundService.directive()` получает `REPLAN recovery.not_dead`; прежний `PhantomBackgroundDecision` оценивал только FARM/TRAVEL/RECOVER, поэтому не предлагал кандидата для обычного visible-farm поведения. Focused regression до fix: 3 PASS / 1 FAIL (`NO_CANDIDATE`); recovery regression: 1 PASS / 3 FAIL (`FAIL_GOAL death.recovered_at_town`).

Внесённые изменения удерживают recovered goal ACTIVE, адресно возобновляют ранее сохранённый `FAILED farm.background` при READY/MATERIALIZED alive и проводят visible candidate через общий server-side AutoPlay/AutoUse micro-loop. Background simulation сохраняет batch путь. На первом deployed JAR естественный profile 2941 прошёл Goal→candidate→handler и native attack. На последнем JAR естественный profile 1348 имел `farm.background ACTIVE`, `candidate.background.farm`, `background.visible.autoplay_started SUCCESS`, native AutoPlay CAST по monster target и изменение live position.
