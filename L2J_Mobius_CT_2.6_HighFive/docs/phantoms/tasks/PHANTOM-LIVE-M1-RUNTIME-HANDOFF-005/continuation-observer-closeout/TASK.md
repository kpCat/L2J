## Обязательный результат
A. M1 использует один неизменяемый снимок наблюдаемой позиции: LIVE у существующего
   проверенного Player, COMMITTED только у действительно STORED; переходные состояния
   не маскируются возвратом к старой точке.
B. Подход с самого начала учитывает движение выбранного Player и завершается встречей,
   а не обязательным достижением устаревших XY. Профиль не подменяется по ходу проверки.
C. Уход и короткий возврат рассчитываются относительно актуального Player. Телепорты
   TestAdmin имеют узкое server-issued разрешение в его текущем consent-сеансе;
   произвольные координаты не разрешаются. Фантома не двигать средствами проверки.
D. «Новая materialization» и «встреча с уже существующим Player» — разные результаты.
   Полный M1 GREEN не выдавать, если первая ветка не наблюдалась или появилась поздно.
E. До arm выполнить регрессии всей цепочки, включая отрицательные случаи, actual
   PowerShell runner с fake transport/clock и короткую native TEST-интеграцию.
F. Затем один connected-сеанс: естественный подход → видимость → native действие
   выбранного фантома/сцены → уход 15 секунд → возврат того же экземпляра → restore/stop.

## Производительность — жёсткие ограничения
- Ни новых background timers/threads, ни SQL на каждый шаг, ни записи live XY в history.
- Не менять PhantomTopologyPositionPublisher, history/ecology/scheduler/AutoPlay/retention
  ради этого RED. Одноразовые operator-методы не переносить в игровой tick.
- Пулы и параметры сохраняются: 1280 READY, 8720 RETIRED, active64, cap128, pulse100ms,
  maxScheduled10000. Не включать глобальный `.play` и не увеличивать caps.
- Подготовка: одна ограниченная выборка кандидатов; текущий выбранный объект — адресный
  поиск в памяти. Не вызывать полный operatorStatus/histogram из каждого Capture.
- Лёгкие снимки не перечисляют мобов/предметы и не читают БД. Census — три фиксированные
  точки сцены с существующим paging, а не на каждом MOVE/WAIT.
- Общий предел connected-run 8 минут; максимум 400 mailbox-запросов, 32 из них резерв
  на cleanup; не повышать лимит mailbox512. Файлы логов не переписывать целиком на каждом tick.

Основной scope задан SOURCE_MAP. Разрешены M1 operator-методы, localplay observer helper,
Pilot actions, существующий runner и их тесты/точечное build wiring. Не добавлять второй runner.

Мутации тестовых персонажей — только в существующей guarded TEST DB.

в изолированной копии после подтверждения текстовой тождественности, не публиковать EOL drift.

## Git и deployment
Разрешены inspection (`status`, `rev-parse`, `diff`, `show`, `ls-remote`, `log` по scope),
`git fetch origin feature/phantom-world`, точечные `add -- <exact paths>`, `commit`,
обычный `push origin HEAD:feature/phantom-world` после проверки актуального remote.
Чистый detached worktree создавать штатным инструментом; при его отсутствии разрешён
`git worktree add --detach <новый свободный путь> <проверенный SHA>`.
Запрещены add ., reset/clean/stash/rebase/force, широкий restore и перезапись чужих hunks.
Перед публикацией проверить состав staged и whitespace. Кодировку проверить один раз
перед финальным кодовым commit; не повторять проверки после каждого диагностического шага.

После focused GREEN — один финальный clean JAR, backup и один owned restart/deploy.
Login JAR и конфигурацию сохранять. Установленный JAR/hash и исходный SHA должны совпадать.
Если меняется только PowerShell после deploy, не пересобирать Java без причины.

## Consent и бюджет взаимодействия
Новый arm попросить только после offline/native TEST, развёртывания, health и preflight.
До свежего подтверждения клиента не перемещать TestAdmin и не запускать PREPARE.
Истёкший невведённый код не считать run; не polling-овать ожидание часами.
После arm — ровно один основной connected-run, один профиль и одна сцена.
Один дополнительный запуск разрешён только при доказанной ошибке самого harness,
когда gameplay-вывод ещё не получен, позиция восстановлена и тот же consent ещё действителен.
Не более двух запусков суммарно; настоящий gameplay RED не переигрывать в поисках PASS.
После Java restart прежний consent не использовать.
