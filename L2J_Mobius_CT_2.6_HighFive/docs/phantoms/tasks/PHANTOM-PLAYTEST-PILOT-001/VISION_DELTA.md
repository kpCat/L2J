# Новые и уточнённые требования — сохранить, но не реализовывать в PILOT-001

Этот документ добавляет продуктовые требования пользователя, не переписывает историческую 146-строчную матрицу и не объявляет новые возможности готовыми. Его нужно сохранить в docs вместе с task outputs. Не запускать повторный полный аудит.

| ID | Требование / уточнение |
|---|---|
| D01 | Один отдельный online персонаж для server-driven проверки; минимум ручных логинов и повторяющихся команд. |
| D02 | Выяснить AFK-disconnect и диагностические flood ограничения; безопасное локальное исключение, не глобальное отключение защиты. |
| D03 | Полноценные PvP/PK и групповые ганги как поведение, а не только единичный combat API. |
| D04 | Самостоятельные профессии 20/40/76, сохранённая последовательная ветка карьеры; правила выбора профы и распределения ролей должны быть явными. Конкретная политика ветвления ещё требует продуктового решения. |
| D05 | Получение и обновление экипировки No/D/C/B/A/S и старших грейдов через доход/покупку/добычу/крафт; не считать equipOwnedItem полноценным развитием шмота. |
| D06 | Карьера и экипировка работают в background как минимум; после materialization/restart состояние согласовано, нет двойной выдачи. |
| D07 | Пати с REAL игроком переживает штатный вход/выход из допустимого instance/Kamaloka/Rift; члены не исчезают только из-за смены topology/locality. |
| D08 | Явные reasons удержания тела (party/instance/combat/store/interaction); это требование результата, конкретная архитектура pins ещё не реализована этой задачей. |
| D09 | Friend/whisper/clan общение с логически online, но dematerialized персонажем; отсутствие тела не должно автоматически означать недоступность всех социальных функций. |
| D10 | Direct party invitation к online dematerialized боту: законное появление/native invitation/решение; не телепортировать его мгновенно к пользователю без правила перемещения. |
| D11 | Самостоятельное создание/вступление/жизнь кланов, не только наличие ClanService. |
| D12 | Native торговля через письма/COD, с реальным переносом предметов/адены и обработкой отказа/истечения; это отдельно от BUY/SELL и offline store. |
| D13 | Пользователь НЕ требует сейчас реализовывать физический фарм эпиков ботами. Редкие эпические предметы должны иногда появляться в продаже очень дорого. Обычные рейды/групповой PvE этим не отменены. |
| D14 | Допустимая модель источника эпиков — нематериальная симуляция с длительностью/cooldown/редким успехом. Реальные epic NPC, их HP, death/spawn/respawn и доступность игрокам НЕ меняются. |
| D15 | Редкая эмиссия эпиков — глобальная квота на мир/период, не шанс для каждого из 10k каждый тик. Durable ledger источника/окна/получателя, no duplicate after restart, bounded offline catchup, запрет накопительного «залпа» за месяцы простоя. Конкретные цены и сроки не выдуманы и в этой задаче не выбираются. |
| D16 | Книги заточки навыков должны поступать в продажу без обязательной реализации Олимпиады. Exact item IDs и варианты обычных/специальных книг брать из реального datapack. Редкость/цены отдельно от эпиков, не объявлять их автоматически одинаковыми. |
| D17 | Источник редкого предмета создаёт один настоящий экземпляр в согласованном inventory/stock, затем обычная торговля. Не переносить виртуальную «награду» повторно при каждой materialization и не печатать unlimited товары. |
| D18 | Native offline-store lifecycle, редкие товары и mail/COD должны быть отдельными проверяемыми сценариями экономики. Пилот не даёт себе эти предметы ради демонстрации. |

Статусы D03–D18 в этой задаче: `NOT_IMPLEMENTED_BY_THIS_TASK`. Они остаются в плане; пользователь не должен напоминать о них после каждой внутренней задачи.
