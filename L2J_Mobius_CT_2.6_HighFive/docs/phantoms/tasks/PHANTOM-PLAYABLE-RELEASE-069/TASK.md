**Цель:** не новый тестовый конвейер, а один самостоятельный, штатно запускаемый High Five release-candidate, в котором можно создать НОВОГО обычного персонажа (access 0) и начать играть, а фантомы выполняют полезную самостоятельную жизнь, экономику, группы и бой. Владелец не участвует в подготовке/тестах, не входит TestAdmin и не создаёт личный игровой персонаж до последнего owner handoff. Действующая ветка `feature/phantom-world`, repository `D:\Codex\repos\L2J-phantom-world`; предварительный GitHub baseline `1741547db89f715ac7ace7cb279bfee335e950ee` после TASK068. Проверить фактический HEAD/remote в начале. Пакет относится исключительно к Java High Five.

## Почему это не ещё одна кампания из восьми синтетических тестов

- Сохранить проверенные B–F TASK068 и M2/M3 SERVER_VERIFIED. Их не переписывать и не требовать полного повторения старых suite.
- M1 G4/G6 — исторические OPEN/DEFERRED; нельзя помечать их задним числом PASS. Вместо них отдельный **игровой** критерий `PLAYER_START_READY` на обычном Main, с явно записанными границами доказательства.
- M5 victory конкретной девятки над boss25199, M6 каждый template, M7 марафон 1–85 не являются необходимыми условиями для начала личной игры. Применять native APIs, проверять общие причины и фиксировать факты.
- Время: до **12 часов wall clock** от первого действия. С **10.5 часов** не начинать новые функциональные разработки; на проверку, safety, документирование, commit/push, поставку. Закончить раньше, если игровые gates выполнены. Не воспроизводить часы ради статистики.

## P0 — обязательные общесерверные игровые правила, не GM-only и не Phantom-only

**0.1 Mana Potion в PvP:** `dist/game/data/stats/items/00700-00799.xml`: item 728 `Mana Potion` связан с `custom/10000-10099.xml` skill10001, ManaHeal100, reuse500ms; item726 `Mana Drug` связан с skill10000. Убрать `player isPvpFlagged=false` только у обеих mana категорий (или минимум728 и явно объяснить726); разрешить использование в PvP/PK/дуэлях при обычной проверке инвентаря и reuse. **Olympiad restriction** (`is_oly_restricted`) оставить до отдельного решения владельца. Не менять HP/CP potions, item consume, cooldown, price/IDs/skill semantics. Обычная Mana Potion становится доступна в Alt+B за **1000 Adena при x1** (только source-supported ID728, без бесплатной выдачи); новая покупка должна списать реальные Adena и выдать предмет.

**0.2 Raid Curse устранить ВЕЗДЕ:** бизнес-правило глобальное и без переключателя, который случайно вернёт окаменение. Аудит всех native/script consumers: `java/.../model/actor/Creature.java` direct melee/skill/heal/buff; `dist/game/data/scripts/ai/bosses/QueenAnt/QueenAnt.java` own aggro curse; `NpcConfig.RAID_DISABLE_CURSE`/`NPC.ini`, skill ids `RAID_CURSE`/`RAID_CURSE2`; другие source references в этой H5. В реальных рейдовых действиях (Player, Phantom, Summon, healer/support) никто не получает ни паралич, ни silence, ни обнуление урона/отказ только за разницу уровней. Прекратить **генерировать raid curse**, убрать мёртвые пути/согласовать устаревший INI. Не удалять общие навыки/Abnormal effects, если они имеют и иное легальное применение; не изменять обычный combat AI/hate/boss HP/MP ради теста.

**0.3 Эпики любого уровня:** провести data/source audit реальных level-only admission barriers: Queen Ant (ID29001, Ant Nest), Core (ID29006, Cruma Tower), Orfen, Baium, Antharas, Valakas, Frintezza/LastImperialTomb, Zaken, Beleth, другие действующие epic-entry families в H5. Явный Frintezza `LastImperialTomb.java` проверяет `channelMember.getLevel() < 80`, пересмотреть level-only части без изменения оплаты, lifecycle/reuse/owner/party/command channel/инстанс-safe/обязательных игровых предметов. Для Core Cruma — подтвердить, что это открытая зона с teleport shortcuts, и писать `NO_LEVEL_GATE` если соответствующего server gate нет; не создавать фиктивный `instance` и не обходить стены. Не принуждать игрока ждать достижения уровня босса для посещения реального доступного логова. Не выдавать автоматическую победу, не снимать ограничения max population, не пересоздавать мёртвых боссов.

**0.4 Overlevel raid drops:** независимо от curse и входа, `NpcTemplate.calculateDrops` применяет `DropAdena/DropItem*LevelDifference`; для всех настоящих RaidBoss и GrandBoss сделать **отсутствие дополнительного понижающего фильтра из-за разницы уровней** (игрок lvl70+ против Queen Ant, Core), без увеличения базовых таблиц, стандартных chances, общей Adena economy и item-specific exclusions. Для обычных монстров level-gap penalty остаётся stock. Уровневые EXP/SP формулы не менять без отдельного решения; 70+ QA может не дать EXP, но rare loot не должен искусственно падать до 10% только из-за уровня. Компоненты должны проверять actual `isRaid`, в том числе group/owner logic и minions по фактическому role. Не мутировать Lua/client.
