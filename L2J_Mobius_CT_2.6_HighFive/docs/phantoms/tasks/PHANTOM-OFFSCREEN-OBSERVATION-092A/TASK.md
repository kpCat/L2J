# PHANTOM-OFFSCREEN-OBSERVATION-092A — real observer admission foundation

Дата: 25.10.2026. Стартовый published baseline `63f7c819c3ea51d7b1bbe83476e590bdb235180b`, `kpCat/L2J`, ветка `feature/phantom-world`, Git root `D:\Codex\repos\L2J-phantom-world`, module `L2J_Mobius_CT_2.6_HighFive`.

## Почему этот пакет отличается от 092

`TOTAL092=PARTIAL/TEST_ONLY`: read-only graph0 proof найден, production=0, native=0; опубликован отчёт `docs/phantoms/reports/PHANTOM-OFFSCREEN-WORLD-TRAVEL-092.md`. Остановившими причинами стали (a) потеря недавнего human-observation после dematerialize, (b) усечённый до 256 `onlineHumanPoints` без полноты, (c) отсутствие typed commit-time binding для offscreen transition. В ЭТОМ пакете решаем только **(a) и (b)**, создаём доступный настоящему runtime **консервативный observer admission primitive**. Не реализуем сам переход, graph0/farm или (c). Не переименовывать этот результат в FULL092.

## Поставляемое изменение

1. `PhantomMaterializationRetentionPolicy` обязан сохранять время последнего подтверждённого наблюдения реальным человеком после перехода актёра в STORED/дематериализации в пределах текущего штатного `recentHumanMillis` (в production = 60000). `observe(materialized=false)` и `refresh(materializedProfiles)` не должны досрочно забывать метку. Истёкшие записи автоматически удаляются ограниченным способом, без перманентной памяти на тысячи давно неактивных профилей. НЕ превращать STORED в materialized/retain и НЕ расширять разрешение на native actions. Отдельный read-only primitive должен показывать, сохраняется ли блокирующее недавнее наблюдение. Для неизвестного/свежего состояния после рестарта нельзя ошибочно возвращать разрешение.
2. Добавить/внедрить один production API `offscreenObserverAdmission` (имя на усмотрение, один ясный интерфейс) — потребитель будущей 092B, **не действие телепортации**. Входы: точные `profileId`, source и destination `PhantomTopologyPoint`, `instanceId=0`, callback/факты live human census + recent-human clock. Результат: typed `ALLOW` только при подтверждённой полноте и отсутствии угроз, иначе typed `DENY_*`/`UNKNOWN_*` с причиной. Не использовать для этого существующий усечённый `PhantomSystem.onlineHumanPoints()` как полный список.
3. Census source — штатный `World.getInstance().getPlayers()`, фильтр фактического human с native connected client + existing `LOCALPLAY_TEST_HUMAN`; headless/Phantom/offline owner не становится real observer. Сохранить `LocalPlayPilotService.autonomousObservationPoint()` как консервативную simulation/QA human threat при отсутствии ordinary connected human (никогда не считать его доказательством безопасности). Достаточно bounded 257 inspected human candidates: если их больше 256 — explicit `HUMAN_CENSUS_OVERFLOW`, **не разрешение**. Любая ошибка/uncertain data — `UNKNOWN`, не ALLOW. Перепроверять актуальные координаты source/dest при каждом вызове, без использования устаревшей копии `onlineHumanPoints`/`PhysicalDemand.overflow` (последний означает overflow профилей, а не людей).
4. Оба конца должны оцениваться консервативно через existing `PhantomNativeLocalityEnvelope.prewarm` (2 native surrounding regions, включая Z-слой/instance), не только XY distance. Не одобрять null/world-invalid/неподходящий instance/незавершённую cold-start grace. Снимок допуска — read-only и краткоживущий; будущая 092B обязана вызвать его снова непосредственно перед canonical commit. **В этом пакете такой commit не выполняется.**
5. Не изменять `PhantomSystem.onlineHumanPoints()` semantics для обычных signal/locality pipeline и не менять поведение real players/GM/normal path/GK/Rift. Новый primitive может быть отдельным классом в `phantoms/activity` или `topology`, но используемый `PhantomSystem` production façade/поставщик должен существовать, без прямых DB или новых scheduler threads. Разрешён narrow refactor для избежания повторной логики humanObserver.

## Жёсткий scope / work budget

Ожидаемые production изменения: `PhantomMaterializationRetentionPolicy.java`, `PhantomSystem.java`, максимум один новый компактный `PhantomOffscreenObserverAdmission.java`; плюс 1-2 адресных тестовых файла, 1 итоговый отчёт. Обоснованный соседний production-файл допускается только для компиляции/инварианта и документируется до изменения. `PhantomBackgroundState[Codec]`, `PhantomBackgroundTransaction`, `PhantomHistoricalBackgroundPlanner`, `PhantomVisibleFarmTravel`, GameServer core/Npc/World, SQL, teleports и Player native lifecycle **вне изменений**.

Проверь root/module `AGENTS.md`, task instructions, `docs/phantoms/CODEX_WORKFLOW_CONTRACT.md`, `RELEASE_CONTRACT.md`, reports 091/092, оригинальные nearby tests и `SOURCE_MAP.md`. SHA манифеста, фактический local/upstream/live HEAD. Если более новый, read-only сверить последнюю историю, не reset/force. Структурный conflict -> BLOCKED с кратким объяснением без нового отчёта/коммита, не 20-минутный тестовый стенд.

Сначала один targeted RED на утрату recent-human + truncated census; затем **production fix**, focused GREEN/negative, ближайшие retention/locality regressions. Один полноценный Ant compile/JAR если нужен для production; одна обоснованная correction после конкретной compile error. НЕ разворачивать TEST092 DB, GEO203, 5000 профилей, 128 actors, own shadow inventory из тысячи файлов, новые runtime процессы. Избегать дорогостоящей `World.getPlayers()` перепроверки на каждом pulse: данный admission вызывается только когда будущий offscreen transit инициирован, а не на каждом тике каждого Phantom.
