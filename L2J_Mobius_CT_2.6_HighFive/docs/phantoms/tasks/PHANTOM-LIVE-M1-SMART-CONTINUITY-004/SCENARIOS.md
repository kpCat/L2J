# SCENARIOS

## S1 — promotion without stale failure backoff

A natural ordinary profile is outside native could-know range. REAL TestAdmin approaches a source-backed prewarm point.

Expected:
- human-local/relevance is accepted;
- policy admission does not inherit an old 30-second transient-failure delay;
- materialization happens before native could-know/visible entry;
- no pop-in caused by stale backoff.

## S2 — short leave and return is continuous

With the same live Phantom:

- TestAdmin leaves native could-know/locality;
- Phantom enters RECENT_HUMAN soft retention rather than immediate teardown;
- TestAdmin returns within the soft window (the live check may use ~15–30 s; the full ~60 s expiry is automated);
- same materialized Player/object remains; no dematerialize/rematerialize churn.

Do not require a live 60+ second wait solely to prove expiry; focused automated time control is sufficient.

## S3 — party safety

Focused test only for this task:

- materialized Phantom is in a native Party with a REAL Player;
- locality disappears / demotion is requested;
- REAL_PARTY hard reason blocks ordinary dematerialization;
- after real membership ends and no other reason exists, normal soft/demotion rules resume.

Do not expand to full M2 chat/follow/support acceptance.

## S4 — failed route adapts

Create/reuse a focused native/guarded test where the first otherwise suitable farm destination produces a terminal local navigation failure.

Expected:
- travel signal is withdrawn on terminal failure;
- first route/destination gets a bounded transient reachability exclusion;
- high-level `farm.background` intention survives;
- planner chooses another suitable reachable candidate/anchor;
- the Phantom does not remain materialized IDLE retrying the same impossible path forever.

## S5 — one connected visible-life sample

In the single final live session, at least one natural ordinary Phantom must be in an explainable useful state:

- native farming action, or
- actual native movement/travel toward a valid farm destination, or
- bounded recovery.

An alive, solo, no-store, ACTIVE farm Phantom that remains AutoPlay-off/IDLE with repeated route/no-target failures is RED.

A bounded census is diagnostic only; no minimum number of locations/profiles is required.
