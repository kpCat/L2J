# Сохранение настроек владельца

Для обычной настройки Codex и PowerShell-команды не нужны:

1. Вручную измените нужные публичные значения INI в `dist/game/config/`, включая `Custom/` и вложенные каталоги.
2. Дважды щёлкните **SaveOwnerConfig.bat** в папке High Five. Батник сам найдёт проект, выполнит `Save`, затем `Verify` и оставит окно открытым. Права администратора не нужны.
3. При ошибке прочитайте имя файла/ключа и причину конфликта. Сообщения об успехе при ошибке не будет. Исправьте конфликт и повторите запуск.
4. В GitKraken проверьте diff INI и owner-profile файлов, затем самостоятельно сделайте commit и push. Батник и скрипт не выполняют Git-запись и не обращаются к remote.

`dist/game/config/OwnerConfig.json` — единый профиль публичных overrides. Он хранит только отклонения, их управляемые исходные значения и примитивные типы, а также классификацию публичных файлов. Заводские значения всех INI в snapshot не копируются. Для новых overrides `Save` сравнивает текущие INI с их управляемой версией в локальном Git HEAD. У уже сохранённого override исходное значение сохраняется между commit: обычный commit ваших настроек не стирает намерение владельца. Возврат к записанному исходному значению с последующим Save снимает override.

Текущие `OwnerProfile38.tsv` и `OwnerProfilePreserved.properties` остаются проверяемыми проекциями обязательных правил TASK075. Явный `Save` согласует изменённые публичные INI-правила и quest baseline, затем запускает существующую проверку 38/38. Не нужно вручную менять SHA в Java. Обычные Verify/Apply и сборка новые значения в baseline автоматически не принимают. Исходный пакет TASK075, его `OWNER_PROFILE_38.tsv` и исторические SHA не редактируются.

При обычной Ant-сборке сохранённые overrides автоматически применяются **по ключам** перед проверкой 38/38. Candidate builder использует тот же механизм для свежей копии. Новые параметры разработчика и комментарии остаются на месте; старый INI целиком поверх нового не копируется. Для сборки с несохранённой ручной правкой сначала запустите батник. Для Save нужны локальный Git и JDK25, уже используемые проектом; Apply к подготовленной копии не требует remote или отдельного приложения.

Новые INI обнаруживаются рекурсивно. Неизвестный файл не считается публичным автоматически. После проверки его содержимого разработчик или владелец может добавить комментарий `# OwnerConfig: public`; перечень известных конфигов в коде скрипта менять не нужно. Управляемый исходный файл/ключ должен существовать в Git, прежде чем на него можно сохранить пользовательский override. Добавление параметра сервером и пользовательское изменение его значения — отдельные действия: скрипт не придумывает отсутствующие настройки.

Database.ini, Network.ini, конфиги подключения/паролей и приватные данные исключены. В смешанных публичных файлах account/character allowlists, credentials и другие чувствительные ключи также не сохраняются. Отметка публичности не отменяет эти запреты. Не помещайте секреты в произвольные игровые строки: автоматическая классификация не заменяет просмотр содержимого неизвестного файла перед его объявлением публичным.

Удалённый или переименованный сохранённый ключ, дубликат, несовместимый тип, недопустимое обязательное значение либо небезопасный путь дают конфликт. Перед записью проверяются все затронутые файлы. При конфликте применения конфиги не переписываются; при ошибке файловой записи выполняется восстановление сохранённых исходных байтов. Профиль не подбирает новое имя ключа автоматически. Повторные Save/Apply/Verify без новых изменений не должны создавать diff.

Сохраняются текущие ограничения игровых маршрутов: Servitor Share 0..100, Cubic 1..1440 минут, MerchantLinesPerStore 1..20, базовые warehouse slots меньше300. Проверка примитивных типов произвольных новых параметров не доказывает корректность их игрового поведения.

XML не входит в область универсального INI-механизма. Правила заточки остаются в текущем TSV и XML/XSD verifier. Обычный runtime ceiling сейчас +25; для меньшего максимума нужны согласованные XML/TSV, нулевые шансы на максимуме и выше. Special/support ID и пределы сверяются с явными typed-группами `scroll.preserved.N` / `support.preserved.N`, N1..65535, в preserved baseline. Исторический пакет для этого не изменяется.

Для подготовки новой копии разработчиком доступны те же операции из корня High Five:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\OwnerConfig.ps1 -Action Apply -GameRoot <путь-к-свежей-game>
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\OwnerConfig.ps1 -Action Verify -GameRoot <путь-к-game>
```

Вручную запускать их для обычного сохранения не требуется: достаточно батника и GitKraken.
