# LIVE-003-0B — ACTIVE admission и private runtime

Дата: 22.09.2026. Ветка: `feature/phantom-world`. Проверенный исходный HEAD: `8676bbf8dcf78b73686b0601d101740b704a43fa`.

## Причина и исправление

`PhantomPopulationManager.rebalanceAdmissionLocked` выбирал ACTIVE IDs и региональные квоты до полного ecology predicate. Запрещённые профили занимали admission; поздний fence в schedule не освобождал слот для разрешённого. Воспроизводящий A01 на прежнем production-коде упал именно здесь: ожидался admitted ID `[1]`, получено `[]`.

Теперь manager проверяет полный `PhantomPopulationEcologyService.permitsSchedulingLocked` до квот и выбора, используя один sampled `Instant` control pulse. Ecology callback помечает admission dirty и запускает обычный schedule path; финальная проверка перед signal остаётся. Добавлены агрегированные desired / eligible / admitted / effective / World-materialized snapshots и `//phantom status <profileId>` с native reason, scheduler transition и последним отказом materialization. Основной status доступен администратору при выключенном trace; не-GM получает отказ до operator handler. После независимого ревью исправлен cache отказов: новое отклонение заменяет предыдущее, успех очищает его. Отказы cleanup остаются видны через scheduler/lifecycle, а не этот cache. Новых workers, DB lookup на idle pulse, schema, provider и обхода lifecycle нет.
