## Причина launcher drift

Перед правкой source и private START/CHECK/STOP различались. Source сравнивал строковый `startTimeUtc` с `[string]` значением после `ConvertFrom-Json`, которое PowerShell уже преобразовал в `DateTime`. Private копии заменили сравнение на `DateTime`, но только в private runtime; private START вдобавок принудительно скрывал окна и писал stdout/stderr, source START запускал видимо. Это произошло как private delivery в LIVE-003-0B и не стало canonical source изменением. SHA private JAR до доставки: `3B7D421924A5702CB6D8183422494FE94A77430DE03251F2E3E212334D452F15`.

При некорректной/потерянной PID записи START удалял записи и запускал новую JVM. `Wait-TcpPort` принимал открытый порт без проверки PID владельца, поэтому принимал 2106/7777 старой pair за успешный старт новых child. Два повторных START оставили дополнительные GameServer PID 30392/23120, не владевшие 7777. CHECK смотрел только record и называл действующие Login PID 23464 и Game PID 9240 остановленными/устаревшими, хотя те владели 2106/9014 и 7777. STOP останавливал только записанные новые PID, удалял record и печатал «Остановка завершена» без итоговой проверки; исходная pair оставалась живой. Ранее ручной exact `Stop-Process -Id 9240,23464` закрыл её порты. Эти факты подтверждены `EVIDENCE.md`; визуальное отсутствие Phantom на Talking Island не объясняет причину materialization без native snapshot.

## Изменение

- Source `LocalPlay-Ownership.ps1` теперь задаёт один contract для всех трёх entrypoint: record `format=2`, role, PID, UTC ticks, JAR, SHA-256 runtime identity; JVM получает отдельные `-Dphantom.localplay.runtime` и `-Dphantom.localplay.role` без изменения `java.cfg`. Legacy JSON распознаётся как stale evidence. Ownership восстанавливается по exact marker/role/JAR и всем ожидаемым listener PID, неоднозначные/чужие владельцы блокируются. Процесс до открытия listener можно остановить только при точном совпадении валидного v2 record с marker и UTC ticks; missing/stale record без порта для STOP недостаточен.
- START по умолчанию создаёт видимые окна, `-Background` скрывает их и перенаправляет stdout/stderr в private `local-play/logs`. Уже работающая exact pair даёт `ALREADY RUNNING` и exit 0 без новой JVM. CHECK показывает PID, stale-record и владельцев 2106/9014/7777; STOP завершает только доказанные owned PID и печатает успех после проверки exit и закрытых портов. `Build-LocalPlay.ps1` теперь включает общий helper в будущий runtime build.
- Штатный voiced handler `.phantomstatus [profileId]` зарегистрирован в `MasterHandler`. Он требует `PersonalCharacterQoLService.isPersonalUser(player)`, который исключает headless session, читает только `PhantomSystem.operatorStatus()` и `operatorAdmissionProfile()`, выводит native admission/ecology и exact profile scheduler/worldPresent/failure. GM `//phantom` и общий `Say2` не менялись; nonallowlisted получает отказ.
- В admission suite добавлены отдельные deterministic A09 READY-after-bootstrap/fenced и A10 minute-boundary manager/ecology assertions. Они прошли на текущем production code без дополнительной правки manager.
