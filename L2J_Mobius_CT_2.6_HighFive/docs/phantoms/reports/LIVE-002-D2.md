## Read-first и причина

До изменения прочитаны `TASK.md`, `EVIDENCE.md`, `ACCEPTANCE.md`, модульный `AGENTS.md`, `README.md`, workflow и task standard, D1 report/STATE/manifest/witness rows; затем planner, authority, service, transaction, operation key, state, native `TeleportHolder`/`TeleporterData` и ближайшие topology/Goal033A/transaction тесты. Отдельные `CURRENT_GENERATOR_STATE.*`, `CONTEXT_INDEX.md`, `DEVELOPMENT_CHAT_HANDOFF.md`, `docs/AGENTS.md` и code-map в модуле не найдены. Bounded exception к лимиту дополнительных exact reads и 8–10 файлов: D2 требует одновременно генератор, runtime route owner, planner, authority, transaction call sites и guarded integration. Независимые subsystems, schema, Unity, provider, rates, population, schedules, heap/collector и QoL не менялись.

Root cause подтверждён до патча: `PhantomHistoricalBackgroundPlanner.candidate` принимал только topology `routeHint` с BACKGROUND edges; `L2jPhantomBackgroundAuthority.advanceTravel` продвигал только topology edges; `PhantomBackgroundService` передавал travel transaction пустую item delta. D1 `FACTUAL_NORMAL`/GeoEngine connectors оставались TSV evidence без executable leg и fee path, поэтому Dwarf e4b/e904 не могли исполниться даже при структурной достижимости.

Переиспользован existing-owner путь: D1 machine builder и C topology anchors; один immutable `PhantomNormalGatekeeperTravel` с типизированными topology/GK steps используют planner и authority. Existing `PhantomBackgroundTransaction` по-прежнему единственный владелец canonical записи. Новый state machine и DB schema не добавлены.
