## Ограниченный бюджет исправлений checkpoint/release

- Обычные feature goals сохраняют явно заданный scope.
- Checkpoint/release closure может явно разрешить ограниченный бюджет прямых исправлений; бюджет по умолчанию при таком разрешении — не более двух прямых блокеров.
- Исправление допустимо только на текущем причинном пути при точной root cause, с переиспользованием существующего канонического контракта, без schema/migration, нового worker/timer/cache, глобальной policy, публичного redesign или новой функции.
- После каждого исправления выполняется focused regression, затем продолжается исходный checkpoint.
- Для каждого локального прямого блокера не создаётся отдельный suffix/micro-goal.
- Третий независимый блокер или архитектурная неоднозначность означают честный `BLOCKED`.

## Эффективность и подготовка задач

- Task package должен содержать pre-audited факты и узкие read-first пути.
- Принятые исторические goals и отчёты не перечитываются без необходимости.
- Между milestones используются focused gates; soak и полные release gates запускаются только при реальном milestone closure.
- Рекомендация модели и reasoning является orchestration metadata вне task package и команды `/goal`.
- Рекомендация по умолчанию: GPT-5.6 Sol / Medium. High применяется только для реальной multi-owner архитектуры, тонкой конкурентности, restart/recovery или idempotency. Very High применяется лишь для исключительных блокеров, а не «для надёжности».
