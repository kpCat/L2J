# OWNER FINAL RELEASE TARGETS — Phantom World

**Владелец подтвердил 24.10.2026.** Это постоянный обязательный продуктовый контракт для планирования финального развёртывания. Задача 079 должна положить этот текст в tracked `docs/phantoms/OWNER_FINAL_RELEASE_TARGETS.md` (при существовании документа — merge, без потери). Настоящий документ — **цель**, НЕ отчёт о выполненной настройке и НЕ разрешение создавать персонажей или предметы во время 079.

## 1. Население и материализация

- **5000 различных постоянных автономных Phantom profiles/identities** с индивидуальными именами, классами, историями/памятью, календарями и сохранением после restart. Это НЕ 5000 full Java `Player` одновременно. Имена уникальны в native client limits, без GM masquerade; кириллица требует отдельной end-to-end проверки клиента/БД, транслит допустим.
- **До 128 одновременно материализованных Phantom `Player` как начальная целевая конфигурация (cap не меньше 128)** с возможностью повышения после фактического RAM/CPU/latency теста. Динамический ACTIVE/cap/human-demand, без исчезновения на глазах, cap release/priority для настоящего игрока. Не путать число сохранённых, scheduler ACTIVE и physical materialized. Настройка `MaxMaterializedPhantoms=128` сама по себе не доказывает фактическую нагрузочную пригодность. Не обещать гарантированное «ровно 128 рядом со мной».
- Поэтапная нагрузочная проверка перед промоушеном 500→1000→3000→5000: native profile persist, GameServer heap/GC/CPU, MariaDB write/read, scheduler backlog, World/known-list, start/stop/restart consistency, p95 важной работы, отсутствие неконтролируемых потоков и OOM. Цель 5000 считается достигнутой только при реальных 5000 durable с профильными расходами и restart continuity. Если железо или архитектура ограничивают, не лгать: дать измеренный максимум и адресный backlog, не выдать половину за успешный финал.

## 2. Сотни частных торговцев `.offline`

- **Не меньше 200 одновременно реально открытых native `.offline` SELL/BUY/MANUFACTURE лавок** в поддержанной конфигурации; желаемая эксплуатационная цель **300–500**, когда производительность и честное наличие товаров подтверждены. `MerchantTargetStores`/`MerchantHardCap`, `PhantomMarketMaximumOpenStores` и native offline trade settings разделять по owner; не заявлять 200 из одного `MerchantTargetStores=200`. Разнообразные товары N–S80, shots/spiritshots, crystals, recipes, materials, enchants, jewelry, equipment, известные источники, реальные цены и ценность. Не гарантировать каждый товар сразу.
- Открыты настоящими `Player` с допустимым native stock/fees/ownership и ненулевым inventory, могут быть дешёвыми offline holders без 200 ACTIVE AI. Лавки не должны стоять в одной точке; разделение/площадь Гирана и других торговых зон, стабильные имена/цены, восстановление sameDB restart один раз, без duplicate goods/Adena, infinite virtual credit, бесплатных S80/эпиков и магической торговли. Экономика ограниченно растёт из настоящего фарма/торговли/крафта/фоновой причинной симуляции.

## 3. Игровые конфигурации и Alt+B

- Финальный сервер должен реально включать **кастомную Community Board (`CustomCommunityBoard=True`)**, проверять штатную работу её HTML/handlers/включённых согласованных разделов, отдельный private store item broker `_bbsmarket` с SELL/BUY/CRAFT, категориями, поиском, ценами и `Radar.addMarker`. Не путать наличие source HTML с activated effective runtime. Не включать случайно бесплатные S80, утечки GM/admin, сломанные multisell, мгновенную бесконечную торговлю; все QoL-покупки/телепорты должны соблюдать цену/допуск, согласованные ранее.
- **Все ранее согласованные персональные QoL** доступны для владельца через существующие `PersonalCharacterQoL.ini`, `PersonalPremiumQoL.ini`, `PersonalProgressionQoL.ini`, `CommunityBoard.ini` и т.п.: support/buff/effect durations, личные навыки, crystallization, Seven Signs, ограниченные solo Kamaloka/Labyrinth/Rift, fishing aid, Henna, положительное усиление augmentation, Wondrous Cubic cooldown, personal premium shop и overlevel relief там, где это предусмотрено. Фактические ключи/значения обязаны быть read-first проверены; переключатели должны быть effective в candidate. НЕ распространять персональные исключения на всех Phantom и обычных игроков, НЕ выдавать GM. Глобальные изменения типа AutoNoblesse требуют отдельного решения владельца, не включать автоматически лишь потому что «всё QoL».
- **Владелец введёт конкретный идентификатор при финальном развёртывании.** `AllowedAccounts` — имена учётных записей, `AllowedCharacterIds` — числовые object IDs; nickname персонажа не является заменой account. Уточнить у владельца корректный *логин аккаунта* и при необходимости object ID **только в финальной подготовке**; не придумывать ник и не включать wildcard/all. Секретные allowlist, Database.ini, Network.ini и пароли не класть в Git/ZIP.
- Владелец самостоятельно отредактирует все нужные `dist/game/config/**/*.ini` (рейты XP/SP/drop/quest, балансы/цены, class/skill/QoL, население), затем **один раз запустит `SaveOwnerConfig.bat` (выполняет Save→Verify)**; осмотрит Git diff и сам сделает commit/push через GitKraken. Финальная сборка должна применять OwnerConfig `Save→Verify` к source и `Apply→Verify` к staged copy, без обнуления изменённых владельцем значений, с конфликтами вместо молчаливого дрейфа. Нельзя снова развернуть demo preset `32/8/cap32` или отключённый custom Alt+B, как было в 078.

## 5. Принятие финала

Финальный GREEN запрещён без: 5000 durable unique profiles, начального cap128+ и доказанной материальной устойчивости, ≥200 native offline stores, кастомного Alt+B и пользовательских QoL effective при точном owner account, личной сохранённой конфигурации/рейтов, чистого restart/STOP и принятой владельцем игры. Поэтапный progress и готовность серверных функций можно принимать частями, но **финальный целевой релиз — весь контракт**.
