# Phantom World v4 — куда двигаться после первых 200 реплик

Это редакционный план, **не новый технический контракт**. Актуальные ID категорий, голоса, режимы и события задаёт официальный паспорт `CHATGPT_GENERATION_RU.md`. Первая партия: `hybrid.trade.absurd_offers / REPLY 200`; импорт и отдельный Java consumer уже проверены. Реальный игровой v4 не включён.

## Почему первая партия получилась слабой

Независимый аудит оригинального `phantom_world_absurd_epic_replies_200.jsonl` (200 записей):
- `voices:["ANY"]` — **10/200 (5%)**, остальные сильно привязаны к голосам и зачастую facets.
- `profanity!=NONE` — **12/200 (6%)**: 2 MILD и 10 STRONG.
- `maturity=MATURE` — **10/200 (5%)**, но это **десять грубых ругательств**, а не разнообразные сексуальные шутки.
- Ни «целка», ни «девственность» в тексте не встречаются; нет заметной отдельной линии взрослого сексуального юмора. Результат выглядит обеззараженным и повторяет узкие формулы.
- Технически `count=200`, нормализованных дублей внутри партии нет, поэтому Studio приняла её закономерно. **LOCAL_VERIFY_PASS не означает литературное качество.**

## Полноценная мини-тема: сначала смысл, потом слова

Заказы делаем последовательно: **REPLY** (что говорит фантом) → **TRIGGER** (что он понимает от собеседника) → опциональная **INITIATIVE** только при зарегистрированном событии. Не пытаться поместить все три типа в один файл. Обширная категория может содержать несколько непохожих по сценам REPLY batches: флирт, токсичный юмор, спокойные реакции, сдержанные продавцы. Без семантических входов сотни ответов не будут автоматически звучать в ответ на любые сообщения игроков.

Чтобы получить похожую на человеческую жизнь речь, нельзя отдавать все усилия торговле эпиком: надо систематически охватывать бытовые темы, конфликт, дружбу, PvP, будни группы, экономику и смешанный юмор. Ниже редакционные идеи для зарегистрированных leaf из паспорта (названия ID точные).

**Контекст сексуального торга:** общая `hybrid.trade.absurd_offers` не знает, что именно игрок предлагает — носок или девственность. Реплика с «целкой» может оказаться не к месту. Для сугубо интимных предложений используй отдельную `hybrid.trade.romantic_barter` с собственными TRIGGER+REPLY; если этот смысл слишком узок/не подходит, добавь через reviewed registry отдельную категорию `hybrid.trade.adult_absurd_offers` и экспортируй новый паспорт. Только после её регистрации и поддержки runtime можно генерировать готовый файл для неё. Живое общение важнее выполнения процента любой ценой.

## Как заказывать партиями, не зная JSON

**Пример 1 — переделываем торговую тему (REPLY):**

> Сделай 200 новых REPLY для абсурдного торга в Lineage 2. Первая партия получилась стерильной: теперь нужны разные взрослые ситуации, едкий юмор, натуральный мат 25–35%, сексуально-бытовые двусмысленности 10–15%. Не зацикливайся на одном предмете и одной формуле шутки. Голоса ANY 65–75%, остальные — разные архетипы. Дай готовый проверенный JSONL. Это *новая партия*, а не исправление уже импортированного файла.

**Пример 2 — та же тема, но TRIGGER:**

> Создай 200 TRIGGER (фраз, которые реально напишут игроки) про абсурдные предложения обменять эпики на всякую ерунду, в том числе грубые, пошлые, ироничные, с ошибками и игровым жаргоном. Не придумывай ответы бота; для каждой записи укажи intent из паспорта, уместные ambiguity и не заявляй свободного понимания языка. Готовый JSONL.

**Пример 3 — первая «человеческая» категория:**

> Сделай 200 REPLY о бытовой усталости после работы: с разными характерами, иногда ругань, иногда серьёзная поддержка, ирония над начальником и жизнью. Категорию выбери из паспорта. Это не торговля и не PvP. Готовый JSONL.

**Пример 4 — реакция на грубость:**

> Сделай 200 REPLY о том, как разные фантомы воспринимают мат и оскорбления: один спокойно шутит, другой отвечает грубо, третий устанавливает границы. Не путай «сам матерится» с «терпит личные нападки». Категорию выбери из паспорта. Готовый JSONL.

**Пример 5 — разрешённая инициатива:**

> Сделай 100 INITIATIVE после подтверждённого события PvP-победы для подходящей PvP-категории из паспорта. Игроки могут радоваться, материться, подкалывать друг друга и сохранять достоинство. Никаких выдуманных убийств или событий. Готовый JSONL.

**Пример 6 — не знаешь следующую тему:**

> Предложи мне 15 независимых мини-тем для живого общения Phantom World, которых мы ещё не обсуждали. Для каждой — существующая категория, 3–5 разных ситуаций и какие файлы REPLY/TRIGGER можно заказать. JSONL пока не создавай.

## Проверки и реальный игровой эффект

`STAGED / LOCAL_VERIFY_PASS` подтверждает формат и собранный pack, `JAVA_CONSUMER_PASS` — что его читает Java. Только `INSTALLED` и явный `EnablePhantomSemanticV4=True` означают подключение к игровому серверу. Предыдущие stage неизменяемы: новая сборка имеет новый SHA. Повторный импорт не заменяет старые записи, он **добавляет** новые; для удаления/пересборки без старой партии нужен отдельный безопасный workflow, не ручное удаление файлов из workspace.

Сейчас Java v4 допускает `MATURE` и любой `profanity!=NONE` только при `whisper`, `consentingPhantom` и остальных правилах; `FLIRT` и `AGGRESSIVE_BANTER` ограничены ещё и знакомством/доверием. **Поэтому даже 30% мата в JSONL не создадут 30% мата в публичном игровом чате.** Не подделывать метки ради обхода. Это отдельное продуктовое решение о фильтрах, а не дефект литературной генерации.

Важная разница: **200 REPLY не умеют ничего распознавать**; к ним нужны TRIGGER по той же leaf, а текущий Java matcher — буквальные нормализованные совпадения, не универсальный анализ русского языка. 100 INITIATIVE для рейда/торговли без зарегистрированного event будут отклонены — доступны только четыре PvP-события в паспорте.

Редакторское качество важно выше скорости: сначала полнота 20–40 действительно разных жизненных сцен, потом объём фраз. После новых batches используй «Пример ответа» с разными голосами/отношениями и при необходимости общую отдельную Java content проверку; не надо запускать Codex ради каждой генерации.
