## Проверенные промежуточные экономические контракты

`PhantomEnchantExpectedCost` решает конечную систему линейных ожиданий для уровней `0..N-1` и выбирает дешёвый допустимый route policy. Для каждого шага `p` берётся из `EnchantScroll.getChance` + scroll/support bonus с cap 100%, failure state — DESTROY, RESET_TO_ZERO или RETAIN_LEVEL из stock scroll type. Учитываются повторные попытки, expected base items/destructions/resets, scroll/support counts и только подтверждённая компенсация crystals (пока 0, без подтверждённого crystal fair anchor). Near-zero chance и превышение safe bound исключаются. `PhantomCanonicalEnchantRoutes` читает фактические H5 `EnchantItemData`/`EnchantItemGroupsData` и отбрасывает scroll/support без положительного source-backed fair input через ту же authority. Реальный D-weapon scroll `955` и stock chance `+1..+3 = 100%`, шаг `+3→+4 = 66%` сверены в тесте. Chance меняется в `dist/game/data/EnchantItemGroups.xml`, safe range вытекает из его групп (`general 0..2`, full armor `0..3`), stock max текущего datapack — 16, scroll max/applicability — `EnchantItemData.xml`, дополнительные player ограничения — `Player.ini`; для этих loaded stock owners требуется restart Game Server; после него следующая quote строится из новых данных, отдельной Phantom копии chance нет.

`PhantomRecipeExpectedCost` вычисляет `C = (Σ quantity_i × legitimateInputCost_i + feePerAttempt) / ordinaryYieldPerAttempt`, где `ordinaryYieldPerAttempt = successRate × (1−masterworkDiversion) × productCount`, с bounded recursive BOM, cycle guard и редким masterwork diversion по `CraftMasterworkChanceRate`; вход без anchor исключает recipe. Тестовый 60% рецепт с inputs 70 и fee 5 дал expected 125 за обычную готовую вещь, а рекурсивный intermediate и цикл проверены отдельно. Когда drop/spoil/NPC purchase source ингредиента не даёт цену, `L_npc` от stock Merchant выступает канонической нижней границей альтернативной стоимости расходуемого ингредиента, а не выдуманной гарантированной ценой его покупки. Это ограничивает SELL готового изделия снизу; реальная acquisition стоимость такого ингредиента может быть выше. `PhantomPrivateMarketQuote` получает fair/craft/enchant floors и фактический NPC acquisition как независимые inputs: `Bid = min(max(L_npc, floor(Fair×(1−discount))), P_npc−1)` при существующем `P_npc`; невозможный `L_npc≥P_npc` исключает BUY. `Ask = max(ceil(Fair×(1+premium)), CraftFloor, EnchantFloor, L_npc+1, Bid+1)`. `discount/premium` читаются из `PhantomMarket.ini`, strict `0..2500` bps, default `500/500`. Stock `RequestSellItem` payout (`referencePrice/2`, независимо от enchant) и custom `MerchantZeroSellPrice` проверены фактическим `Item` fixture. `PhantomNpcAcquisitionPrice` использует loaded BuyList/Product, видимого Merchant и его castle/base tax; реальный list `382/1463` дал taxed `P_npc=16`, `L_npc=7`, `Bid=15`, `Ask=17`. При неразрешённом источнике/tax BUY не публикуется.

## Алгебра и область применимости

Для допустимого spawned attackable non-raid NPC `n` authority берёт из accepted indexed knowledge ожидаемые `Y_A(n)` Adena и `Y_i(n)` предмета за убийство. Ungrouped chance ограничивается 100%; для stock grouped default учитывается cumulative порядок, а при custom chance rate применяется stock per-line branch (его occurrence cap может уменьшить фактический yield). Относящиеся к death/spoil amount/chance множители и item-specific overrides из `Rates.ini` применяются к соответствующей стороне, включая отдельный Adena item `57`. Если одновременно Adena и supply растут в пять раз до caps при том же источнике, `Y_A/Y_i` сохраняется; supply быстрее Adena снижает quote, Adena быстрее supply повышает её. `F_loot(i)=min_n(Y_A(n)/Y_i(n))` — прозрачная opportunity-price proxy, **не** точная статистика всех игроков или произвольный множитель от reference price. Group cap, смена минимального источника и NPC/liquidation floors объясняют отклонения от идеального равенства.

Для реального stock Merchant `P_npc=min_visible (long)(Product.price × (1+castleTax+baseTax))` с stock siege-guard adjustment, non-GM eligibility и наличием limited stock. `L_npc` — stock обычная ликвидация `referencePrice/2` либо 0 в `MerchantZeroSellPrice` режиме. Цена входа `F_source=max(L_npc, min(P_npc если точен, F_loot если доступен))`; когда нет никакой purchase/drop/spoil цены, положительный `L_npc` остаётся **нижней границей альтернативной стоимости** обычного item/recipe input, а не утверждением о цене покупки. Для расходуемых enchant scroll/support вход без реального положительного purchase/drop/spoil источника исключается даже при `L_npc>0`. Отсутствие даже этой границы исключает ordinary item. Нулевой доступный ordinary NPC source исключает Phantom BUY/SELL, нерешённый налог/source исключает BUY. `F_craft=(Σ q_j×F_input(j)+fee_per_attempt)/(successRate/100×(1−rareDiversion)×ordinaryYieldCount)`; production self-craft не имеет обязательной Adena fee, поэтому источник fee равен 0. Native MANUFACTURE листинг с fee 0 остаётся coherent: заказчик предоставляет те же материалы, готовое SELL не ниже F_craft. `F_base=max(F_source,F_craft,L_npc)`.

Для enchanted item `F_+N=F_base+E[scroll/support expense + replacement destroyed bases − only defensible crystal recovery]`. `PhantomEnchantExpectedCost` выбирает минимальную legal step policy и решает конечную линейную систему для failure state; scroll/support candidates оцениваются той же source authority. Свиток/поддержка допускается только при положительной фактической обычной NPC purchase либо ordinary non-raid drop/spoil scarcity цене; одной Merchant liquidation floor для расходуемого enchant input недостаточно. Stock normal failure уничтожает, blessed возвращает в 0, safe оставляет уровень. Crystal recovery в текущей quote равно 0: stock service может выдать crystals, но без доказанной цены конкретного объёма и grade нельзя безосновательно вычитать их стоимость. В native BUY нельзя указать enchant level, поэтому BUY nonstackable gear исключён; enchanted SELL получает полный F_+N. Цена не зависит от собственного Phantom листинга, фиксированного процента за +N нет. `Bid=max(L_npc,floor(F_base×(1−buyBps/10000)))`, при точном `P_npc` дополнительно строго ниже P, иначе order исключён; `Ask=max(ceil(F×(1+askBps/10000)),F_craft,F_+N,L_npc+1,Bid+1)`. Integer arithmetic и safe Adena bounds проверены.

Authority строит eligible-NPC index один раз на quote generation, читает immutable snapshot/hash и кэширует item/NPC fair inputs внутри plan; он не перечитывает весь datapack на каждом scheduler tick. Смена loaded rates/config/recipe/enchant данных требует restart для пересчёта следующего plan; уже открытый listing не переписывается в обход exact goal target.
