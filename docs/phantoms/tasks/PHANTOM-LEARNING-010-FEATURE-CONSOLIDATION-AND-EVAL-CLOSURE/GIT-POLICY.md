# Git-политика после консолидации

1. Единственная постоянная ветка разработки: `feature/phantom-world`.
2. Каждая следующая задача стартует от проверенного `origin/feature/phantom-world`, работает со своими проверенными исходниками и завершает обычным scoped push **напрямую в feature**. Никаких постоянных WIP-веток по номеру задачи.
3. Пользовательские локальные изменения в известных worktree сохранять, никогда не делать `reset --hard`, `clean`, `stash pop`, force push ради удобства Codex.
4. Изолированный TEST GameServer/SQL/weights может находиться вне основного checkout; отдельная среда не равна отдельной Git-истории.
5. Перед каждым Goal и после него — независимый GitHub HEAD, commit diff/source validation, проверка DIRTY и upstream. Не заявлять «всё интегрировано», пока факты не проверены.
6. Временные экспериментальные ветки допустимы лишь при отдельно согласованном риске; они не должны оставаться второй основной веткой и должны быть интегрированы после независимого теста.
7. Никакого автоматического включения DRAFT/обучения в MAIN, даже если код тренера уже присутствует в feature.
